## 2. Какие данные обрабатываются

### 2.1 Локально на устройстве (IndexedDB, не покидает устройство без явного действия)

- Записи употребления: вещество, способ, количество, единица, время, заметки.
- Партии и дозировка: остаток, концентрация.
- Отметки самочувствия, вода, часы сна.
- PIN-код (блокирует интерфейс; **не шифрует хранилище** — честно сказано в Settings.tsx:246).
- Экспорт/импорт данных — только по явному действию пользователя; экспорт шифруется WebCrypto, при недоступности WebCrypto экспорт прерывается (открытый текст не сохраняется).

### 2.2 Telegram initData (при открытии как Mini App)

- `user.id` — идентификатор для привязки данных при синхронизации.
- Валидация HMAC-SHA256 + срок auth_date (см. BACKEND-DECISION.md). initData не логируется, не передаётся третьим лицам.

### 2.3 Обезличенная аналитика (PostHog EU Cloud, eu.i.posthog.com)

Фактический allowlist (analytics.ts): app_open[source], screen_view[name], record_created[], record_repeated[], record_undone[], stats_viewed[], safety_opened[], app_error[class].

Настройки: autocapture=false, disable_session_recording=true, ip=false, property_denylist [$ip,$host,$browser,$os,$device_type,$current_url,$pathname], anonymous distinct_id (без user id/initData).

**Никогда не отправляются**: названия веществ, способы, дозы, заметки, timestamps записей, initData, user id, любые PII. Ключ phc_ — публичный write-only, намеренно в коде.

### 2.4 Синхронизация (когда будет включена, сейчас выключена)

- Записи с operationId, user_id, revision — на сервер оператора (кандидат: VPS NL, см. BACKEND-DECISION.md).
- Чувствительные поля шифруются at rest (Fernet/pgcrypto), ключ отдельно от данных (Developer Terms §4.4).
- Статусы честно: «Сохранено на устройстве» / «Ждёт отправки» / «Синхронизировано» / «Не удалось синхронизировать».

## 3. Правовые основания (GDPR Art. 9)

Данные об употреблении ПАВ = special category health data (Art. 9(1)). Обработка запрещена кроме исключений:

- **Основное: Art. 9(2)(a) explicit consent** — явное, конкретное, активное, отзываемое согласие пользователя (совпадает с Developer Terms §4.3: individual, explicit, active, revocable consent). Согласие собирается до первой записи/синхронизации, отдельным экраном, не пре-чекбоксом. Отзыв — в Настройках, с удалением данных.
- Для НКО-модели (если MTÜ): Art. 9(2)(d) not-for-profit body с philosophical aim — только члены/regular contact, без раскрытия наружу без согласия.
- Для B2B с клиниками/public health: Art. 9(2)(h)/(i) на basis of law + professional secrecy (п.3) — отдельный договор, не этот драфт.
- Art. 9(4): Member States могут вводить дополнительные условия для health data — юрисдикционная вариативность оговаривается при выборе юрлица (Эстония MTÜ — кандидат, см. JURISDICTION-MONETIZATION.md).

Локальное хранение на устройстве пользователя без передачи оператору не является обработкой оператором в смысле GDPR — но политика описывает и его для прозрачности.

## 4. Цели обработки

- Предоставление функции дневника (запись, просмотр, статистика).
- Синхронизация между устройствами пользователя (по согласию).
- Обезличенная продуктовая аналитика (улучшение приложения).
- Безопасность: валидация initData, защита от подделки запросов.

Никакой рекламы, продажи данных, профилирования для третьих лиц.

## 5. Хранение и удаление

- Локальные данные: до удаления пользователем («Удалить все данные» → «Точно?» → «Это навсегда.»).
- Серверные данные (при включённой синхронизации): до отзыва согласия/запроса удаления; удаляются по запросу пользователя или Telegram (Developer Terms §4.2), когда retention больше не нужен, при прекращении работы Приложения, по lawful request.
- Бэкапы: pg_dump cron, проверка восстановлением; удаление распространяется на бэкапы в разумный срок.
- PostHog: обезличенные события, retention по настройкам проекта EU Cloud.

## 6. Права пользователя

Доступ, исправление, удаление, экспорт (встроен в Приложение), отзыв согласия, жалоба в надзорный орган. Контакт: [email владельца]. Срок ответа: 30 дней (GDPR).

## 7. Безопасность

- Шифрование at rest для чувствительных полей, ключ отдельно от данных (§4.4).
- HTTPS обязателен (Pages https_enforced=true; API только TLS).
- initData HMAC + TTL, constant-time compare.
- Токены/API-ключи конфиденциальны, не публикуются (§4.5).
- Уведомление о breach — без неоправданной задержки (§4.4).
- SOS локальный: приложение не звонит автоматически, «Звонок не подтверждён», «Всё запускается только вами» (ADR 0001, индустриальная норма — Brave FAQ «never automatically send anything to 911»).

## 8. Дети

Приложение не предназначено для лиц младше 18 лет. Данные несовершеннолетних сознательно не собираются.

## 9. Изменения политики

Уведомление в Приложении/боте до вступления изменений в силу. Продолжение использования = согласие с новой редакцией для не-special-category данных; для health data — повторное explicit consent.
